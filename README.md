# Club Manager

Система керування користувацькими сеансами та доступом до програмного забезпечення
для комп'ютерних клубів, навчальних класів та інших приміщень із загальнодоступними ПК.

Адміністратор із центральної панелі бачить стан усіх комп'ютерів, відкриває й завершує
сеанси, веде облікові записи клієнтів із балансом хвилин, визначає, які програми дозволено
запускати, і отримує звіти. На клієнтських ПК працює агент, який блокує робоче місце поза
сеансом, показує таймер і стежить за запущеними програмами.

## 1. Як це влаштовано

```
 Панель адміністратора (браузер)
            │  HTTP: REST API, вхід за логіном і паролем
            ▼
 ┌─────────────────────────────┐     ┌───────────┐
 │  Сервер  Club.Server        │─────│  SQLite   │ club.db
 │  ASP.NET Core + SignalR     │     └───────────┘
 └─────────────────────────────┘
            ▲  WebSocket (SignalR) поверх HTTPS: постійне з'єднання,
            │  ключ агента, перевірка сертифіката сервера за відбитком
            │
 ┌──────────┴──────────────────┐
 │  Клієнтський ПК (кожен)     │
 │                             │
 │  Club.Agent — служба        │  SYSTEM: команди сервера, контроль програм,
 │        ▲                    │          перезапуск оболонки
 │        │ named pipes        │
 │        ▼                    │
 │  Club.Shell — оболонка      │  сеанс користувача: екран блокування,
 │                             │  форма входу, таймер, вітрина програм
 └─────────────────────────────┘
```

| Проєкт | Що це | Де працює |
|---|---|---|
| `src/Club.Server` | Сервер: база даних, логіка сеансів, панель адміністратора (`wwwroot`), звіти | ПК адміністратора |
| `src/Club.Agent` | Агент — служба Windows | Кожен клієнтський ПК |
| `src/Club.Shell` | Оболонка — екран блокування, таймер, вітрина програм | Кожен клієнтський ПК |
| `src/Club.Shared` | Спільні класи повідомлень між сервером, агентом і оболонкою | — |
| `scripts/` | Скрипти збирання, встановлення, видалення | — |

Головні принципи:

- **Сервер — єдине джерело правди.** Час сеансу рахує сервер; клієнтський ПК лише показує таймер.
  Змінити системний годинник чи закрити програму на ПК недостатньо, щоб отримати безкоштовний час.
- **Fail-closed.** Якщо щось іде не так (немає зв'язку з сервером, агент недоступний),
  ПК переходить у заблокований стан, а не залишається відкритим.
- **Найменші привілеї.** Клієнти працюють під звичайним обліковим записом Windows і не можуть
  змінити файли агента, прочитати його ключ чи надіслати службі команди.

## 2. Вимоги

**ПК адміністратора (сервер)**
- Windows 10/11 x64.
- Для збирання: [.NET 10 SDK](https://dotnet.microsoft.com/download/dotnet/10.0) або Visual Studio 2026
  (робочі навантаження «ASP.NET and web development» і «.NET desktop development»).
- Сервер і клієнтські ПК мають бути в одній мережі; клієнти мають досягати сервера на TCP-порту **5001** (HTTPS).

**Клієнтські ПК**
- Windows 10/11 x64 будь-якої редакції (Home теж підходить).
- Встановлювати .NET не потрібно — агент збирається разом із середовищем виконання.
- Два облікові записи Windows (див. розділ 4): адміністратор і стандартний користувач для клієнтів.

## 3. Встановлення сервера

### 3.1. Збирання

**Варіант А — через Visual Studio (для розробки).**
Відкрийте `ClubManager.slnx`, у Solution Explorer клацніть правою кнопкою на `Club.Server` →
**Set as Startup Project**, натисніть ▶.

**Варіант Б — окремою програмою (для постійної роботи).**
Двічі клацніть `scripts\publish-server.cmd`. З'явиться папка `publish\ClubServer`.
Скопіюйте її в зручне місце (наприклад, `C:\ClubServer`) і запускайте `Club.Server.exe`
**з цієї папки** — поруч із ним створиться база `club.db`.

### 3.2. Налаштування

Перед першим запуском відкрийте `appsettings.json` сервера
(`src\Club.Server\appsettings.json` або `publish\ClubServer\appsettings.json`):

```json
"HttpPort": 5000,
"HttpsPort": 5001,
"CertificatePath": "server-cert.pfx",
"AgentKey": "change-me-club-2026",
"AllowRemoteAdmin": false,
```

- **`AgentKey`** — секретний ключ, за яким сервер приймає агентів. **Обов'язково змініть** на власний
  довгий випадковий рядок і запам'ятайте: той самий ключ потрібно вказати в агенті (розділ 5.1).
- **`AllowRemoteAdmin`** — `false`: панель відкривається лише на самому сервері (`127.0.0.1`);
  `true`: також з інших ПК мережі за адресою `https://<IP сервера>:5001` (вхід за логіном і паролем;
  браузер попередить про самопідписаний сертифікат — це очікувано).
- **`HttpPort` / `HttpsPort`** — порти. HTTP (5000) працює лише на самому сервері, для панелі;
  HTTPS (5001) — для агентів і віддаленого доступу.

### 3.3. Сертифікат сервера

Під час першого запуску сервер сам створює TLS-сертифікат (`server-cert.pfx`) і записує його
**відбиток** (SHA-256) у файл `server-cert.thumbprint.txt` поруч, а також виводить у консоль.
Агенти підключаються лише до сервера з саме цим сертифікатом (certificate pinning), тому
встановлювати сертифікат на клієнтські ПК не потрібно, а підмінити сервер неможливо.

- Не видаляйте `server-cert.pfx`: з новим сертифікатом агенти перестануть підключатися,
  доки ви не оновите в них відбиток.
- Сервер, запущений з Visual Studio, і сервер із `publish\ClubServer` мають **різні** сертифікати
  (кожен створює свій). Оберіть один спосіб запуску для постійної роботи.

### 3.4. Брандмауер

Один раз запустіть `scripts\allow-firewall.cmd` **від імені адміністратора**
(правий клік → «Запуск від імені адміністратора»). Скрипт дозволяє вхідні з'єднання на порт 5001
і відповіді на ping.

### 3.5. Адреса сервера

Дізнайтеся IP-адресу сервера в локальній мережі: командний рядок → `ipconfig` → рядок `IPv4 Address`
потрібного адаптера (наприклад, `192.168.1.10`). Ця адреса знадобиться для агентів.

### 3.6. Перший вхід

1. Запустіть сервер і відкрийте в браузері **http://127.0.0.1:5000**.
2. Увійдіть як **admin / admin**.
3. Одразу натисніть **«Змінити пароль»** угорі сторінки.

## 4. Підготовка клієнтських ПК

На кожному клієнтському ПК потрібні два облікові записи Windows:

| Обліковий запис | Тип | Для чого |
|---|---|---|
| `clubadmin` (будь-яка назва) | **Адміністратор** | Встановлення й оновлення агента, обслуговування |
| `player` (будь-яка назва) | **Стандартний користувач** | Під ним працюють клієнти клубу |

Це важливо: захист файлів агента працює лише проти стандартних користувачів.
Адміністратор Windows може зупинити службу агента.

Як налаштувати:
1. Увійдіть під наявним обліковим записом-адміністратором.
2. **Параметри → Облікові записи → Інші користувачі → Додати обліковий запис** — створіть потрібні записи.
3. Там само кнопкою **«Змінити тип облікового запису»** встановіть типи, як у таблиці.

Перевірте, що клієнтський ПК бачить сервер: `ping <IP сервера>`.

## 5. Встановлення агента на клієнтський ПК

### 5.1. Збирання агента (на ПК адміністратора)

1. Хоча б раз запустіть сервер, щоб він створив сертифікат (розділ 3.3).
2. Відкрийте `src\Club.Agent\appsettings.json` і вкажіть:
   - **`ServerUrl`** — адреса сервера з розділу 3.5, наприклад `https://192.168.1.10:5001`;
   - **`AgentKey`** — той самий ключ, що в `appsettings.json` сервера.
3. Двічі клацніть `scripts\publish-agent.cmd`.
   Буде створено папку `publish\ClubAgent` з агентом, оболонкою і скриптами встановлення.
   Скрипт **сам впише відбиток сертифіката сервера** (`ServerCertThumbprint`) у налаштування агента;
   якщо замість цього з'явиться попередження, запустіть сервер і повторіть.

### 5.2. Встановлення (на кожному клієнтському ПК)

1. Скопіюйте папку `publish\ClubAgent` на клієнтський ПК у **`C:\ClubAgent`**
   (флешка, мережева папка тощо).
2. Відкрийте **командний рядок від імені адміністратора**: Пуск → введіть `cmd` →
   правий клік на «Командний рядок» → **«Запуск від імені адміністратора»**.
3. Виконайте:
   ```
   C:\ClubAgent\install-agent.cmd
   ```
   Скрипт:
   - реєструє службу **ClubAgent** з автозапуском і автоматичним перезапуском у разі збою;
   - додає оболонку в автозапуск і одразу її запускає;
   - виставляє права доступу на `C:\ClubAgent` (користувачі — лише читання й запуск;
     `appsettings.json` і журнал — лише адміністратори).
4. Через кілька секунд з'явиться екран блокування, а в панелі адміністратора — новий ПК зі статусом «онлайн».

Ім'я ПК у панелі — це ім'я комп'ютера Windows. Його можна змінити в панелі кнопкою ✎.
**Кожен клієнтський ПК повинен мати унікальне ім'я Windows.**

## 6. Оновлення та видалення агента

Після встановлення файли в `C:\ClubAgent` може змінювати лише адміністратор,
тому всі дії виконуються в **командному рядку від імені адміністратора**.

**Оновлення** (нова версія лежить, наприклад, у `D:\ClubAgent` або в мережевій папці):
```
C:\ClubAgent\uninstall-agent.cmd
robocopy "D:\ClubAgent" "C:\ClubAgent" /E
C:\ClubAgent\install-agent.cmd
```

**Видалення:**
```
C:\ClubAgent\uninstall-agent.cmd
rmdir /s /q C:\ClubAgent
```

`uninstall-agent.cmd` спершу зупиняє службу (інакше вона одразу перезапустила б оболонку),
потім закриває оболонку і прибирає її з автозапуску.

## 7. Робота з панеллю адміністратора

Панель: **http://127.0.0.1:5000** на самому сервері (або `https://<IP сервера>:5001` з інших ПК, якщо `AllowRemoteAdmin = true`).

### 7.1. Комп'ютери

Для кожного ПК показано: мережу (онлайн/офлайн), навантаження агента (процесор, пам'ять),
**версію агента** з датою збірки (ПК зі старішою версією, ніж на інших, позначено «стара версія»),
поточний сеанс і залишок часу.

| Кнопка | Дія |
|---|---|
| **Гостьовий сеанс** | Відкрити ПК на N хвилин без облікового запису клієнта |
| **+ час** | Додати хвилини гостьовому сеансу |
| **Завершити** | Завершити будь-який сеанс |
| **Повідомлення** | Показати текст на екрані ПК |
| **Блок** | Під час сеансу — **призупинити** його (див. 9.2); без сеансу — просто заблокувати |
| **Розблок** | Відновити призупинений сеанс; без сеансу — відкрити ПК без обмеження часу |
| **Перезавантажити / Вимкнути** | Перезавантажити чи вимкнути ПК; поточний сеанс завершується |

### 7.2. Види сеансів

| Вид | Хто відкриває | Час | Контроль програм |
|---|---|---|---|
| **Клієнтський** | Клієнт сам, логіном і паролем на екрані ПК | Обмежений балансом; списується фактично використаний час | Так |
| **Гостьовий** | Адміністратор у панелі | Задається вручну | Так |
| **Службовий** | Адміністратор своїм логіном на екрані ПК | Без таймера (запобіжник — 24 год) | **Ні** |

### 7.3. Клієнти

- **+ Новий клієнт** — логін (від 3 символів), пароль (від 4 символів), початковий баланс у хвилинах.
- **Поповнити** — додати хвилини; якщо клієнт зараз грає, його сеанс подовжується одразу.
- **Пароль** — встановити новий пароль.
- **Заблокувати** — клієнт не зможе увійти; якщо він зараз грає, сеанс завершується.
- **Видалити** (лише власник) — обліковий запис видаляється разом із невикористаним балансом;
  якщо клієнт зараз грає, сеанс завершується. Історія сеансів і поповнень залишається у звітах.

Логін має бути унікальним серед **усіх** облікових записів — і клієнтів, і адміністраторів,
бо на екрані входу ПК вони спільні. Регістр і пробіли на краях не враховуються (`Test` = `test`).

### 7.4. Дозволені програми

Каталог програм, які клієнти можуть запускати з вітрини на своєму ПК.

- **+ Програма** — назва у вітрині та **повний шлях до .exe на клієнтських ПК**
  (наприклад, `C:\Games\CS2\cs2.exe`). Програма має бути встановлена за цим шляхом на всіх ПК.
- **Режим контролю** (змінює лише власник):
  - **Спостереження** — програми поза каталогом не закриваються, але кожен запуск записується в журнал.
    Почніть із цього режиму, щоб побачити, що запускається на ваших ПК.
  - **Закривання** — програми поза каталогом закриваються протягом ~3 секунд.
- Завжди дозволені: усе з `C:\Windows`, з папок програм каталогу (ігри часто запускають допоміжні
  `.exe` зі своєї папки) і з папок зі списку `AlwaysAllowedFolders` (розділ 11).

### 7.5. Заборонені програми (чорний список)

Програми з чорного списку закриваються **завжди**: у будь-якому режимі контролю, під час сеансу і навіть
на екрані блокування (наприклад, диспетчер задач, відкритий через Ctrl+Alt+Del, закриється за 1–2 с).
Чорний список має пріоритет над білим і над завжди дозволеними папками, тож ним можна заборонити
і програми з `C:\Windows`. Не діє лише у службових сеансах адміністратора.

- **+ Заборонити** — ім'я файлу (`taskmgr.exe`, можна з `*` і `?`: `cheat*.exe`) або повний шлях до файлу
  чи папки (`C:\Games\Old\`).
- **Додати рекомендовані** — диспетчер задач, редактор реєстру, командний рядок, PowerShell і консоль MMC.
- Власні файли агента і критичні процеси Windows (`explorer.exe`, `winlogon.exe` тощо) не закриваються
  ніколи, навіть якщо їх помилково внести до списку.

Якщо заборонено `cmd.exe`, обслуговування ПК (оновлення агента тощо) виконуйте у **службовому сеансі** —
увійдіть на екрані блокування як адміністратор.

### 7.6. Адміністратори та ролі

| Роль | Може |
|---|---|
| **Власник** | Усе: сеанси, клієнти (зокрема видалення), програми, режим контролю, керування адміністраторами, звіти |
| **Адміністратор зміни** | Сеанси, команди, клієнти, каталог програм |

Розділ «Адміністратори» і посилання «Звіти» бачить лише власник.

### 7.7. Звіти

Посилання **«Звіти»** вгорі панелі (лише для власника). Оберіть період і натисніть «Показати».

- підсумок: кількість сеансів, години роботи ПК, середній сеанс, списані й поповнені хвилини;
- завантаженість кожного ПК у відсотках від тривалості періоду;
- середня кількість зайнятих ПК за годинами доби;
- статистика клієнтів і адміністраторів;
- контроль програм: закриті й помічені програми, найчастіші порушники;
- вимірювання: час виконання команд (мс) і час відновлення зв'язку агентів (с).

Кнопка **«Друк / PDF»** — збереження звіту.

### 7.8. Журнал подій

Унизу панелі — події: хто (адміністратор, клієнт, агент, система), на якому ПК і що зробив.
Кожен запис має кольорову позначку категорії. Фільтри над журналом:

- **ПК** — події конкретного комп'ютера або «панель (без ПК)»: облікові записи, налаштування, входи в панель;
- **Хто** — адміністратори, клієнти, агенти ПК, система;
- **Пошук** — за текстом події або логіном;
- **Показати** — 100, 300 або 1000 останніх записів.

Посилання **«журнал»** біля назви ПК у таблиці комп'ютерів і клік на назві ПК у журналі
одразу показують події лише цього комп'ютера.

## 8. Що бачить клієнт

1. **Екран блокування** на весь екран: годинник і форма входу.
2. Після входу — компактний напівпрозорий **таймер** у правому верхньому куті. Якщо навести на нього мишу,
   з'являються кнопки (таймер можна перетягнути мишею в зручне місце):
   - **Програми** — вітрина дозволених програм, запуск однією кнопкою;
   - **Завершити** — завершити сеанс; невикористаний час залишається на балансі.
3. За 5 хвилин до кінця таймер стає червоним і з'являється попередження.
4. Коли час вичерпано, ПК повертається на екран блокування.
5. **Після кожного сеансу** (клієнтського чи гостьового) усі програми користувача закриваються, а дані входу
   в браузери й месенджери, завантаження і тимчасові файли видаляються — наступний клієнт не потрапить
   у чужі акаунти (див. `SessionCleanup` у розділі 11).

## 9. Правила та тайм-аути

### 9.1. Таблиця тайм-аутів

| Подія | Що відбувається | Через скільки |
|---|---|---|
| Залишилось мало часу | Попередження клієнту, таймер червоний | 5 хв до кінця |
| Агент не має зв'язку з сервером | ПК блокується («Немає зв'язку з сервером») | 30 с |
| ПК зник з мережі (вимкнули, завис) | Сервер завершує сеанс; час списується до моменту зникнення | 60 с |
| Немає дій з клавіатурою/мишею (клієнтський чи гостьовий сеанс) | Попередження, потім сеанс завершується | 29 хв / 30 хв |
| Сеанс призупинено і ніхто його не відновив | Сеанс завершується; час — до моменту призупинення | 30 хв |
| Службовий сеанс адміністратора | Запобіжне завершення | 24 год |
| 5 невдалих спроб входу під одним логіном | Вхід під цим логіном заблоковано | на 1 хв |
| Оболонку закрили (диспетчер задач) | Служба запускає її знову | ~2 с |
| Запущено програму з чорного списку | Програма закривається | 1–2 с |

### 9.2. Призупинений сеанс («Блок» під час сеансу)

- Час клієнта не йде, відлік у панелі «застигає».
- Відновити сеанс може: той самий клієнт (увійшовши знову), той самий адміністратор (для службового
  сеансу) або будь-який адміністратор кнопкою «Розблок» у панелі.
- Інший клієнт увійти не може.
- Адміністратор, увійшовши на цьому ПК своїм логіном, закриває призупинений сеанс і відкриває службовий.

### 9.3. Вхід власника без сервера

Якщо сервер недоступний, на клієнтський ПК може увійти **лише власник** (не адміністратор зміни) —
своїм звичайним логіном і паролем. Відкривається службовий сеанс без контролю програм.

- Агент зберігає для цього **лише хеші паролів** власників (PBKDF2) у
  `C:\ProgramData\ClubAgent\owners.json`, доступному тільки SYSTEM і адміністраторам Windows.
- Сервер оновлює ці дані при кожному підключенні агента, а також коли власник змінює пароль,
  створюється новий власник чи власника видалено.
- Після 5 невдалих спроб — пауза 1 хв.
- Коли зв'язок із сервером відновиться, ПК повертається на екран блокування (увійдіть знову як зазвичай),
  а в журнал записується подія про офлайн-вхід.
- Щоб це працювало, агент має хоча б раз підключитися до сервера після встановлення.

### 9.4. Інші правила

- Клієнт може мати лише **один** сеанс на **одному** ПК одночасно. Адміністратори — кілька службових.
- Сеанс завершується, коли закінчується баланс; хвилини округлюються вгору.
- Під час коректного вимкнення сервер завершує всі сеанси. Якщо сервер аварійно зупинився,
  під час наступного запуску відкриті сеанси закриваються за часом останнього сигналу від ПК —
  клієнтам не списується час простою.

## 10. Безпека

| Загроза | Захід |
|---|---|
| Підбір пароля | Хешування PBKDF2 (паролі в базі не зберігаються); блокування після 5 невдалих спроб |
| Доступ до панелі сторонніх | Вхід за логіном і паролем; cookie `HttpOnly` і `SameSite=Strict`; за замовчуванням панель доступна лише з сервера |
| Перевищення повноважень адміністратора | Ролі (RBAC): власник / адміністратор зміни; журнал усіх дій |
| Підробка агента | Агент підключається з секретним ключем (`AgentKey`) |
| Перехоплення трафіку в мережі (паролі клієнтів, ключ агента) | Обмін агентів із сервером — лише через HTTPS (TLS) |
| Підміна сервера («людина посередині») | Агент перевіряє SHA-256 відбиток сертифіката сервера (certificate pinning) |
| Сервер недоступний, а потрібен доступ до ПК | Офлайн-вхід лише для власників за локальною копією хешу пароля (див. 9.3) |
| Клієнт змінює або видаляє файли агента | Права NTFS: користувачам — лише читання й запуск; ключ і журнал — лише адміністраторам |
| Клієнт надсилає службі команди | Канал стану — лише читання; канал входу приймає тільки запити входу/виходу |
| Клієнт закриває оболонку | Служба перезапускає її в сеансі користувача |
| Обхід через «безкоштовний» час | Час рахує сервер; без зв'язку ПК блокується (fail-closed) |
| Запуск небажаних програм | Білий список із режимами спостереження й закривання |
| Наступний клієнт потрапляє в чужі акаунти (месенджери, браузери) | Після кожного сеансу програми користувача закриваються, дані входу й особисті файли видаляються |
| Доступ клієнта до системних засобів (диспетчер задач, реєстр, командний рядок) | Чорний список: закриття в будь-якому стані ПК, зокрема на екрані блокування |

## 11. Налаштування

**Сервер — `appsettings.json`**

| Параметр | За замовчуванням | Опис |
|---|---|---|
| `HttpPort` | `5000` | HTTP-порт, лише для `127.0.0.1` (панель на самому сервері) |
| `HttpsPort` | `5001` | HTTPS-порт для агентів і віддаленого доступу |
| `CertificatePath` | `server-cert.pfx` | Файл сертифіката (створюється автоматично) |
| `ConnectionStrings:Db` | `Data Source=club.db` | Файл бази даних |
| `AgentKey` | `change-me-club-2026` | Ключ агентів — **змініть** |
| `AllowRemoteAdmin` | `false` | Доступ до панелі з інших ПК |
| `EventRetentionDays` | `180` | Скільки днів зберігати журнал подій (0 — завжди). Сеанси й поповнення для звітів не видаляються |
| `AllowInsecureAgents` | `false` | Тимчасово приймати агентів по HTTP (порт 5000) — лише для оновлення старих агентів, див. розділ 13 |

**Агент — `appsettings.json`** (на клієнтському ПК — `C:\ClubAgent\appsettings.json`,
редагувати можна лише від імені адміністратора)

| Параметр | Опис |
|---|---|
| `ServerUrl` | Адреса сервера, наприклад `https://192.168.1.10:5001` |
| `AgentKey` | Той самий ключ, що на сервері |
| `ServerCertThumbprint` | SHA-256 відбиток сертифіката сервера (вписує `publish-agent.cmd`) |
| `AlwaysAllowedFolders` | Папки, програми з яких дозволені завжди (драйвери, антивірус, компоненти Windows) |
| `CloseAppsOnSessionEnd` | `true` — після сеансу закривати всі програми користувача |
| `SessionCleanup` | Що видаляти з профілю користувача після сеансу: дані Telegram, Discord, профілі браузерів, завантаження, тимчасові файли. Змінні `%APPDATA%`, `%LOCALAPPDATA%`, `%USERPROFILE%` — користувача; `\*` у кінці — видалити лише вміст папки; `HKCU\Розділ\Параметр` — запис у реєстрі користувача (напр., автовхід Steam) |
| `MachineCleanup` | Що видаляти після сеансу на рівні всього ПК від імені SYSTEM — дані входу програм, які зберігають їх у своїй папці встановлення (за замовчуванням Steam: `loginusers.vdf`, `config.vdf`, `ssfn*`). В останній частині шляху можна вказати шаблон з `*` |

Після зміни налаштувань агента перезапустіть службу: `sc stop ClubAgent` і `sc start ClubAgent`.

Журнал агента: `C:\ClubAgent\logs\agent.log` (доступний лише адміністраторам). Коли файл перевищує 5 МБ,
він архівується як `agent.1.log` … `agent.5.log` (найстаріший видаляється), тож журнал займає не більше ~30 МБ.

Обслуговування бази на сервері виконується автоматично раз на 6 годин: видаляються записи журналу подій,
старші за `EventRetentionDays`, і стискається службовий файл SQLite `club.db-wal`.

## 12. Тестовий стенд на VirtualBox

Систему можна перевірити на одному комп'ютері: сервер працює на ньому, клієнтські ПК — віртуальні машини.

1. Встановіть [VirtualBox](https://www.virtualbox.org/) і створіть віртуальну машину з Windows 10/11
   (2 ядра, 3–4 ГБ пам'яті, 50 ГБ диска). Встановіть Guest Additions.
2. **Мережа:** Settings → Network → Adapter 2 → **Host-only Adapter**.
   Комп'ютер-сервер матиме в цій мережі адресу зазвичай `192.168.56.1` — у `ServerUrl` агента
   вкажіть `https://192.168.56.1:5001`.
3. **Спільна папка** для копіювання агента: Settings → Shared Folders → додайте папку `publish` проєкту.
   У віртуальній машині вона доступна як `\\VBoxSvr\<назва>`.
4. Перед експериментами робіть **знімок** (Snapshots → Take), щоб швидко відкотитися.
5. **Другий ПК:** вимкніть першу машину → Clone → **Generate new MAC addresses** → Full clone.
   У клоні обов'язково **перейменуйте комп'ютер** (Settings → System → About → Rename this PC).

## 13. Усунення несправностей

**ПК не з'являється в панелі / агент пише «сервер недоступний»**
- Перевірте з клієнтського ПК: `ping <IP сервера>`.
- Чи виконано `allow-firewall.cmd` на сервері?
- Чи правильні `ServerUrl` і `AgentKey` у `C:\ClubAgent\appsettings.json`?
- Подивіться `C:\ClubAgent\logs\agent.log` (від імені адміністратора) і `sc query ClubAgent`.
- У журналі агента «Сертифікат сервера не збігається з очікуваним» або «Не задано ServerCertThumbprint» —
  відбиток в агента не відповідає сертифікату сервера (сервер створив новий сертифікат або запущений
  інший екземпляр). Зберіть агента заново через `publish-agent.cmd` і оновіть його (розділ 6),
  або впишіть вміст `server-cert.thumbprint.txt` у `C:\ClubAgent\appsettings.json` і перезапустіть службу.

**Після переходу на HTTPS старі агенти не підключаються (ПК заблоковані, офлайн)**
- Агенти версії без HTTPS підключаються по `http://…:5000`, а сервер приймає HTTP лише з 127.0.0.1.
- Тимчасово встановіть у `appsettings.json` сервера `"AllowInsecureAgents": true` і перезапустіть сервер —
  старі агенти підключаться.
- Увійдіть на кожному ПК як адміністратор (службовий сеанс) і оновіть агента (розділ 6).
- Поверніть `"AllowInsecureAgents": false` і перезапустіть сервер.

**Два ПК відображаються як один**
- Обидва мають однакове ім'я Windows (типово після клонування). Перейменуйте один із них.

**«Access is denied» при копіюванні чи запуску скриптів у `C:\ClubAgent`**
- Працюйте з **командного рядка від імені адміністратора** (див. 5.2).
- Якщо доступу немає навіть в адміністратора, відновіть права:
  ```
  takeown /f C:\ClubAgent /a /r /d y
  icacls C:\ClubAgent\* /reset /t /q
  ```
  потім знову запустіть `install-agent.cmd`.

**У режимі закривання закривається потрібна системна програма**
- Знайдіть у журналі шлях до неї й додайте її папку в `AlwaysAllowedFolders` агента.

**Клієнт не може увійти: «На цьому ПК уже йде сеанс»**
- На ПК є активний або призупинений сеанс. Перевірте панель: завершіть його або натисніть «Розблок».

**Панель показує стару версію сторінки**
- Оновіть сторінку з очищенням кешу: Ctrl+F5.

**Зміни в коді «зникають» після збирання у Visual Studio**
- Visual Studio зберігає власні копії відкритих файлів. Якщо файли змінюються поза нею,
  закривайте вкладки (Window → Close All Documents) і вмикайте
  Tools → Options → Environment → Documents → «Reload modified files unless there are unsaved changes».

## 14. Обмеження та можливий розвиток

- **Сертифікат.** Використовується самопідписаний сертифікат із перевіркою за відбитком. У мережі
  з власним центром сертифікації можна замінити `server-cert.pfx` на сертифікат, виданий ним.
- **База даних.** SQLite підходить для одного клубу; для мережі клубів доцільно перейти на PostgreSQL
  (у EF Core це заміна провайдера). Зміни структури бази виконуються без міграцій — під час запуску
  сервер сам додає нові таблиці й стовпці.
- **Оплата.** Поповнення балансу — вручну адміністратором; інтеграція з платіжними системами не реалізована.
- **Тарифи.** Одна ціна хвилини для всіх ПК; тарифи за часом доби чи класом ПК не реалізовані.
- **Захист від досвідченого користувача.** Чорний список закриває системні засоби, але не блокує
  гарячі клавіші; за потреби їх можна додатково обмежити груповими політиками Windows.
